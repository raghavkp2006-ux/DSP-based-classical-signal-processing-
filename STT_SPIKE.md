# On-device speech-to-text spike

Scope: compare three offline Android integration routes for SignalChain. This is a research spike only; no app code or STT dependency was added. Sizes below are approximate download/package sizes, not measured APK deltas for this repository. Model files should be delivered as an optional first-run download rather than embedded in the APK; embedding adds essentially the full model size to the download and installed footprint.

## Comparison

| Option | Added app/runtime and model size | 30 s clip latency on a mid-range Android phone | License | Fit with SignalChain / effort |
|---|---|---|---|---|
| **whisper.cpp through JNI** | Tiny GGML is ~75 MiB unquantized or ~31 MiB for a listed q5 variant; base is ~142 MiB unquantized or ~57 MiB q5. Add a native library for each shipped ABI; its stripped APK delta must be measured in a prototype. | No defensible generic mid-range estimate. One Galaxy S10 Android 12 project benchmark reports **105.6 s** for its ~31 MB tiny build on a 30 s clip (RTF 3.52). Treat that as a warning about configuration sensitivity, not a universal whisper.cpp result. Budget tens of seconds to over a minute until measured on the target device. | whisper.cpp is MIT. Whisper checkpoint terms are separate; verify the selected model card. | **High.** Add NDK/CMake and JNI lifecycle, build/ship ABI-specific native code, manage PCM input and model files, and tune threads/quantization. Existing ORT does not help this engine. The upstream Android sample confirms the native Android path and recommends tiny/base. |
| **sherpa-onnx Whisper** | Current upstream multi-ABI Android AAR is 47.8 MB as a build artifact; the APK includes only packaged ABI libraries (measure the actual delta after ABI filtering). Whisper tiny.en int8 ONNX encoder + decoder are about **117 MB** total (12 MB + 105 MB); the benchmarked multilingual tiny package is ~100 MB. Base benchmark package is ~160 MB. | On a Galaxy S10, the same 30 s benchmark measured **2.07 s** for Whisper tiny and **4.04 s** for Whisper base. This is a useful older-phone reference, not a guarantee; model, thermal state, ABI, and build settings change results. | sherpa-onnx is Apache-2.0. Whisper model terms remain separate. | **Medium.** Whisper-specific APIs avoid writing the autoregressive decoder/tokenization path. It ships native inference libraries, so it overlaps the existing ORT dependency rather than reusing SignalChain's ORT session. Pick only required ABIs to control package size. |
| **Whisper ONNX directly through existing ONNX Runtime** | No new inference runtime dependency: SignalChain already includes `onnxruntime-android:1.18.0`. Plan on roughly **75–120 MB** for a tiny int8 encoder/decoder export or ~140–200 MB for base, depending on export and quantization; these are planning ranges, not measured artifacts. Keep model optional and downloaded. | No reliable target-phone measurement located for this exact route/export. For planning only, assume **5–30 s** for tiny and **15–60 s** for base on a mid-range CPU; benchmark the selected export before committing to UX. ORT server benchmarks are not mobile estimates. | ONNX Runtime is MIT. Whisper weights/export terms are separate; check the selected checkpoint/model card. | **Medium-high to high.** Avoids another runtime binary and reuses the existing dependency, but Whisper needs a correct feature extractor, encoder/decoder loop, tokenizer, timestamps, and tested export-specific I/O. It is materially more work than calling a Whisper-ready sherpa API. |

The sherpa benchmark used a 30-second, mono, 16 kHz PCM WAV and measured inference excluding model download and load. Its published device was a Samsung Galaxy S10 on Android 12. Its whisper.cpp result was dramatically slower than sherpa on that setup, so treat engine/configuration measurement as essential before choosing an engine. [Benchmark method and results](https://github.com/voiceping-ai/android-offline-transcribe)

## Recommendation

Prototype **sherpa-onnx Whisper tiny** first if offline transcription is approved and a roughly 100 MB optional model download plus an ABI-specific native runtime is acceptable. It has a direct Android integration path and the strongest relevant phone measurement found for this comparison. Do not put the model in the base APK. If minimizing duplicate runtime code and app bundle growth outweighs implementation time, prototype direct ORT next, but plan for substantially more Whisper-specific decoding work and no latency promise until tested. Do not select whisper.cpp on paper alone: its compact q5 tiny file is attractive, but the cited Android benchmark is a clear performance concern.

Before a product decision, benchmark on the actual target phone(s), cold and warm model load separately, with representative 30-second recordings. Record APK download delta, installed size, peak memory, transcription latency, and transcript quality. Include thermal throttling and one longer clip. None of these options was benchmarked in SignalChain itself.
